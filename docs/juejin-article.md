# 0 token 精准描述 99.3% 的 UI 变化：把 DOM 当 Ground Truth 用到底

> 开源项目 vlm-diff：https://github.com/shidesheng0218/vlm-diff  
> 英文版：https://dev.to/shidesheng/building-a-visual-regression-tool-with-vlms-and-dom-diffing-1j4m

## 前言

最近在做 UI 自动化回归测试，遇到一个棘手问题：**传统像素 diff 误报太多**（字体渲染抖动、抗锯齿差异），而 **GPT-4V/Claude 这些视觉大模型漏报也很严重**（对细微变化不敏感）。

翻了一圈 Paper，发现今年 3 月发的 [VLM-SubtleBench](https://arxiv.org/abs/2603.07888) 直接把顶级 VLM 打脸了：

- **GPT-5-thinking**：77.8% 准确率（人类基线 95.5%）
- **Claude Sonnet 4**：62.6%
- **GPT-4o**：61.6%

在空间位移检测上更惨：**人类 95%，最强模型只有 59.9%**。而且把前后图拼成一张大图喂给模型，10 类变化里 9 类反而更差。

但 UI 测试场景有个天然优势：**我们有 DOM 结构作为 Ground Truth**。

于是写了这个实验项目 **vlm-diff**，先验证了一个假设：

> **DOM diff + 像素 diff → VLM 分类** 的混合架构，比纯 VLM 方案召回率高 33 个百分点、误报率 0%。

然后在这个基础上又往前走了一步，得到了一个更有意思的结果：

> **DOM diff 不只能告诉你"哪里变了"，还能直接告诉你"变成了什么"——99.3% 的变化区域根本不需要调用 VLM。**

## 核心思路

![架构图](https://raw.githubusercontent.com/shidesheng0218/vlm-diff/master/docs/pipeline-demo.gif)

### Stage 1：确定性检测（0 token）

**DOM Diff**：
- 元素增删（结构路径逐节点对比）
- 位置/尺寸变化（`getBoundingClientRect`，带 1px 抖动容差）
- 文本/样式改动（`textContent`、7 个 `computedStyle` 字段）
- **记录每个字段的 before/after 值**（后面会用到，这是关键）

**像素 Diff**：`pixelmatch` + 连通域聚合，作为 DOM 之外的兜底信号。

**无变化抑制**：
```typescript
if (domChanges.length === 0) {
  return { changed: false, regions: [] };  // DOM 没变 → 直接判定无变化
}
```
这一条规则在 145 对样本上（含 6 对无变化对照）做到了 **139/139 变化全检出、0/6 误报**，且两次运行逐字节一致——纯 VLM 检测做不到这一点（同样模型同样输入，两轮跑出了不同的漏报和一次误报）。

### Stage 2：分层描述——重点来了

之前的架构是：检测到区域 → 裁剪 → 扔给 VLM 分类。但我们后来意识到一个问题：

**DOM diff 早就知道答案的大部分了。**

`backgroundColor: rgb(37,99,235) → rgb(220,38,38)`，规则模板直接就能生成：

> "Element background color changed from blue (rgb(37, 99, 235)) to red (rgb(220, 38, 38))"

为什么要花钱请 VLM 重新从裁剪图里"看出来"？所以现在的架构是每个区域先过一遍路由：

- **Tier A（确定性，0 token）**：颜色、文本、样式属性、元素增删、几何变化——全部模板生成，confidence = 1.0
- **Tier B（VLM）**：只有"像素变了但 DOM 没变"的区域（Canvas 重绘、动画中间帧）才升级给 VLM

几个值得一提的实现细节：

**1. 颜色命名**：计算样式是 `rgb()` 格式，写了个 40 行的锚点色板就近匹配（感知加权 RGB 距离），零依赖。

**2. 根因归因（这个最有意思）**：真实布局变化是级联的——删一张卡片，后面所有兄弟节点的 rect 都会位移。怎么区分"谁主动变了、谁是被动挪了"？看 changedFields：一个区域**只有**几何字段（position/size）变化，而同组里存在带非几何变化（文本/颜色/增删）的区域，它就是"级联追随者"，描述会写成：

> "moved 24px up **as part of a layout shift caused by a nearby change**"

**3. pair 级别类型判定用根因优先**：删卡片时容器收缩区域通常比被删卡片本身还大，按"取最大区域"的惯例会把整对样本误判成 size-change。改成根因区域优先后，离线类型准确率从 82.7% 提到 90.6%。

## 实验数据

### 检测层（145 对，0 API 调用）

139/139 变化对全检出，0/6 无变化误报。

### 真实 API 三臂对照（Kimi K3，15 对代表性子集，跑了两轮）

| 指标 | 纯 VLM 全图 | 管线（无 hint） | 管线 + DOM hint |
|------|------------|----------------|-----------------|
| 召回率（12 变化对） | 66.7% | **100%** | **100%** |
| 无变化误报（3 对） | 33.3% | **0%** | **0%** |
| 端到端类型准确率 | 66.7–75% | 66.7% | **83.3%** |
| 平均输入 tokens/对 | ~1505 | ~583 | ~692 |

**一个反直觉的发现**：单纯"裁剪后分类"是**不行**的——同样的裁剪图，不给 DOM 字段提示时条件分类准确率只有 58–67%（对比全图方案的 100%）。原因是裁剪把类型判断需要的参照系裁掉了：判断圆角变化需要看到其他几个角，判断颜色偏移需要别的色块参照。但把检测器已知的 `changedFields` 作为 ~50 token 的文本提示传给模型，差距就被补回来了（83.3%）。

### 分层路由离线回放（145 对全量，0 API 调用）

| 变化类型 | 区域数 | 确定性描述 | 需 VLM |
|----------|--------|-----------|--------|
| size-change | 136 | 136 | 0 |
| spatial-shift | 122 | 122 | 0 |
| element-remove | 122 | 122 | 0 |
| color-change | 94 | 94 | 0 |
| text-change | 62 | 62 | 0 |
| element-add | 41 | 41 | 0 |
| style-change | 34 | 30 | 4（像素级阴影重绘） |
| **合计** | **611** | **607（99.3%）** | **4（0.7%）** |

**端到端类型准确率 90.6%（126/139），VLM token 消耗为 0**。对比：带 hint 的完整 VLM 管线是 83.3%（且每对 ~692 输入 token）。

也就是说：在 DOM 可观测的回归场景下，**确定性方法的准确率反超了 VLM**，因为 DOM diff 拿到的是精确值，VLM 是在"猜"。

### 真实 API 四臂验证（Kimi K3，36 对，总花费 $0.18）

光离线回放还不够，把 tiered 臂加进真实 API 对照跑了一轮：

| 指标 | **tiered** | 管线+hint | 管线无 hint | 纯 VLM 全图 |
|------|-----------|----------|------------|------------|
| 召回率（30 变化对） | **100%** | 100% | 100% | 76.7% |
| 端到端类型准确率 | **100%**（30/30） | 93.3% | 56.7% | 95.7%（但漏了 7 对） |
| avg tokens/对 | **11+4** | 910+388 | 782+611 | 1505+196 |

三个细节：

1. **75 个区域只有 1 次真实 VLM 调用**（一个像素级阴影重绘产生的"无 DOM 信号"横条），类型准确率 100%
2. **hint 臂的两个错误正好是 tiered 按构造修掉的**：容器膨胀盖过新增元素（根因归因解决）、border 颜色变化被归成 style（模板直接点名属性）
3. **纯 VLM 全图的模式很稳定**：描述能力其实很强（检出时 95.7% 准确），但"找"的能力不行——30 对漏了 7 对，且三轮实验都是同一类失败（细微颜色/位移）

Token 节省 **98.9%**，比当初预估的 60–80% 还要高。

### CI 回归门禁

顺手把回放做成了 CI 门禁：`npm run replay:assert` 会在升级率超过 5% 时 fail——以后谁改了检测/描述逻辑导致本来能确定性描述的区域被迫送 VLM，CI 直接拦住。

## 局限性（坦率版）

1. **升级率有循环论证嫌疑**：数据集的突变本来就是 DOM 可观测的，99.3% 的确定性覆盖在这个 benchmark 上是"应该的"。真实页面（Canvas、图片内容替换、第三方组件）的升级率会是多少，才是真正的开放问题——这也是下一步实验。
2. **fixture 是合成的**：6 个手写页面，没有响应式断点、虚拟滚动、真实广告/时间戳。
3. **无变化样本只有 6 对**：0% 误报的分母太小（95% CI 上界约 39%）。
4. **MVP 只验证了一个中档模型**（Kimi K3）+ 15 对，需要在 Claude/GPT 上复现。
5. **描述质量的裁判评分还没做**：类型准确率是和 ground truth 精确匹配（不需要裁判），但"模板文案 vs VLM 文案哪个更好读"还需要盲评。

## 总结

这次迭代最大的收获是一个思路上的升级：

> **第一阶段我们用 DOM 回答"哪里变了"——这省掉了 VLM 的定位工作。**
> **第二阶段我们用 DOM 回答"变成了什么"——这几乎省掉了整个 VLM。**

不要盲目追求 AI 替代一切。先问一句：**这个领域里有没有结构化的 ground truth，能直接把问题变成确定性的？** 有的话，AI 只需要处理剩下那 0.7%。

前端测试领域还有很多这样的机会：
- **E2E 测试**：LLM 生成 Playwright 脚本 + 静态分析验证选择器稳定性
- **性能监控**：VLM 识别布局抖动 + Lighthouse 量化指标
- **无障碍审计**：VLM 检查视觉问题 + axe-core 校验 ARIA

期待看到更多「混合智能」的探索 🚀
